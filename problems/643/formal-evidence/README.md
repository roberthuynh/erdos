# Lean evidence for supporting bounds

This directory records the source and official `check.sh` receipts for the supporting 3-uniform bounds. The receipt ledger lists 48 historical checks from the M1–M5 development, one separate historical check for the 9/8 bound, and one historical check for the forbidden-configuration bridge. These are copied receipts, not 50 new runs.

`receipt-ledger.json` gives each exact declaration, historical receipt, and the SHA-256 of the original source bytes recorded by that receipt. `source/` contains an export copy of 20 modules, including the local import needed by `Lemma1g`. Some module documentation comments referenced development paths; those comments were removed for this export. `source-transformations.json` records the original and exported SHA-256 for every file. The historical receipts alone do not verify the changed export bytes. The declaration bodies and imports were left unchanged.

The 24/23 bound is `Erdos643R3.Pw2312Main.card_le_choose`; the separate 9/8 bound is `Erdos643R3.WeightingBound.card_le_nine_eighths_choose`. The source is under `source/`, outside any existing public Lean library tree, to avoid merging it with a different package namespace. The current evidence does not contain an unconditional Lean proof of the coefficient-one statement `f(n;3) ≤ (1+o(1)) C(n,2)` or of an exact finite formula.

An [isolated upstream bridge](upstream-bridge/README.md) imports exact Formal Conjectures source files at commit `95b199bf…` and proves that its forbidden predicate and extremal-number expression receive the same 24/23 upper bound. Its direct build, isolated Lake build, axiom probe, and kernel replay receipts are separate from the 50 historical local receipts.

The corrected 24/23 export and its 13 local import-closure modules passed a fresh official `check.sh` run. The [export receipt](receipts-export/Pw2312_card_le_choose.log) records the theorem source hash; `receipt-ledger.json` additionally records the exact hash of every compiled local dependency under `export_checks`. The historical receipts are kept separately from this one fresh export check.

The other seven exported modules also compiled with Lean in the same build directory; the [build log](receipts-export/all20-extra-build.log) and `export_build` ledger entry bind all 20 source hashes. A separate [isolated Lake build](receipts-export/lake-all20.log) passed on all 20 exported modules using the separately verified pinned package cache. It did not redownload dependencies from a clean checkout.

The `standalone/` project pins Lean and Mathlib revisions. With the pinned Lean toolchain installed through [elan](https://github.com/leanprover/elan#installation), Git, Python 3, and GNU `timeout` installed (available through coreutils' `gnubin` directory on macOS), `./prefetch.sh`, `lake exe cache get`, and `lake build` rebuild the exported modules. `check-clean.sh` checks dependency pins, source tokens, axioms and kernel replay. A [fresh phased hardened check](receipts-export/hardened-phased/receipt.json) passed for all 20 exported modules and 50 named supporting declarations, including source scanning, exact dependency pins, environment hygiene, independent axiom agreement, negative controls for user-written unsafe definitions, and kernel replay in three bounded chunks. One full replay repeat timed out at 240 seconds and is recorded as UNKNOWN; no single completed `check-clean.sh` result is claimed. The hygiene tool accepts only three named Lean-generated recursion helpers from safe `PwCheck` definitions. A historical `PASS` is a claim about its recorded original SHA only; any source edit requires its own check.
